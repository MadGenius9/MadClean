# Working on MadClean

## Architecture and commands

Use the existing isolated checkout. Do not create a Git worktree unless the user explicitly asks.

Read README.md and docs/INTEGRATIONS.md before changing Windows behavior. Keep presentation in `src/MadClean.App`, portable policy/models/parsers in `src/MadClean.Core`, Windows adapters in `src/MadClean.Windows`, and boundary tests in `tests`. Use the supported SDK pinned in global.json. Avoid unnecessary runtime dependencies and update package lockfiles deliberately when dependencies change.

From the repository root:

```text
dotnet restore MadClean.sln --locked-mode
dotnet build MadClean.sln -c Release --no-restore
dotnet test tests/MadClean.Tests -c Release --no-build
```

Windows run/package commands are in README.md. On this cloud machine the SDK is `/workspace/.dotnet/dotnet`; set `DOTNET_CLI_HOME=/workspace/.dotnet-home` and `NUGET_PACKAGES=/workspace/.nuget/packages`. .NET runtime IPC may require execution outside the filesystem sandbox. Do not disable TLS, package signatures, artifact verification or assertions to make builds pass.

## Safety invariants

The user separately authorized implementing later roadmap modules; keep them explicitly selected and isolated from inspection, with exact previews and reviewed Windows validation gates. Never infer frozen settings/history, unique/reclaimable bytes or deletion permission. See docs/CLEANUP-SELECTION-REVIEW.md.
- Cleanup inventory uses only explicitly documented temporary roots. No Downloads/documents/saves/credentials/browser-profile sweeps. Never traverse known reparse points; treat locked/inaccessible/recent files conservatively. This inventory does not authorize later deletion. Filesystem races require renewed validation at any future action boundary.
- Selected cleanup-file rechecks are metadata-only, exactly source-bound and separately invoked; see docs/CLEANUP-FILE-EVIDENCE.md. - Selected cleanup stream scope uses exactly two bounded same-handle FileStreamInfo queries and private counted-name comparisons; no content/path enumeration or buffer growth. Alternate/unknown streams force blocked Partial, never eligibility. Preserve zeroed native ownership and fresh error roles.
