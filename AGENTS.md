# Working on MadClean

## Architecture and commands

Use the existing isolated checkout. Do not create a Git worktree unless the user explicitly asks.

Read README.md and docs/INTEGRATIONS.md before changing Windows behavior. Keep presentation in `src/MadClean.App`, portable policy/models/parsers in `src/MadClean.Core`, Windows adapters in `src/MadClean.Windows`, and boundary tests in `tests`. Use the supported SDK pinned in global.json. Avoid unnecessary runtime dependencies and update package lockfiles deliberately when dependencies change.

From the repository root:

```text
dotnet restore MadClean.sln --locked-mode
dotnet build MadClean.sln -c Release --no-restore
dotnet test tests/MadClean.Tests -c Release --no-build
```

Windows run/package commands are in README.md. On this cloud machine the SDK is `/workspace/.dotnet/dotnet`; set `DOTNET_CLI_HOME=/workspace/.dotnet-home` and `NUGET_PACKAGES=/workspace/.nuget/packages`. .NET runtime IPC may require execution outside the filesystem sandbox. Do not disable TLS, package signatures, artifact verification or assertions to make builds pass.

## Safety invariants

- The phase-one foundation and ordinary inspection are read only: they must never invoke cleanup/deletion, registry modification, startup toggles, malware scans/remediation, installation, elevation or restart APIs. The user separately authorized implementing later roadmap modules; keep them explicitly selected and isolated from inspection, with exact previews and reviewed Windows validation gates. Disabled production execution must have no environment/configuration/UI bypass. Passive writes are limited to MadClean's local activity log, explicitly selected persistent cleanup exclusions under its local settings folder, and development build outputs/provider-owned metadata refresh. Development fixtures may change only their exact owned files/registry subtree, never real startup entries or servicing/update state.
- Cleanup inventory uses only explicitly documented temporary roots. No Downloads/documents/saves/credentials/browser-profile sweeps. Never traverse known reparse points; treat locked/inaccessible/recent files conservatively. This inventory does not authorize later deletion. Filesystem races require renewed validation at any future action boundary.
- Installed-app registration metadata must use the fixed-capacity native enumeration/value whitelist and bounded decoder. Do not restore whole-name-array or unbounded GetValue fallbacks. UninstallString/QuietUninstallString receive only NULL-data existence queries, never content reads. Malformed or oversized fields retain unknown/partial coverage and cannot become complete baselines or action eligibility.
- Selected MSI verification is an explicit read-only product-code/context metadata lookup using MsiEnumProductsExW and MsiGetProductInfoExW only. Keep NULL input SID/current-user scope, both SID output pointers NULL, source-derived context masks, fixed buffers/whitelisted properties, same-thread enumeration, native worker ownership and honest Partial/Unknown outcomes. No package paths, all-user enumeration, MsiOpenProduct, activation/self-repair, msiexec, configure/install/uninstall or elevation. NoRemove restrictions remain visible; matching display/context metadata never authorizes an action or authenticates a package/publisher. Ordinary inspection never invokes this lookup.
- Windows-package discovery is a separate explicit current-user Appx Main/Bundle metadata query through the fixed system PowerShell/Appx module. No AllUsers/User/SID/volume/manifest/installation-path/dependency/provisioning/deployment/repair/removal queries or actions. Missing flags and warning presence remain unknown/Partial; NonRemovable and SignatureKind are reported metadata, never trust or action permission. Preserve separate ARP and package collections/counts/baselines; rows can overlap and are not unique apps. Package identities, raw provider output and search terms never enter logs or screenshots after actual data loading.
- No executing discovered startup commands, resolving arbitrary scripts, loading plugins, accepting source agreements, PowerShell policy bypass, or executing package installation commands.
- Fixed read-only PowerShell scripts use system PowerShell, encoded arguments, no profiles and no interactive prompts. WinGet uses the user's App Installer alias, not PATH/current-directory lookup. Preserve cancellation, timeouts, process-tree cleanup and output bounds.
- Unknown/unavailable/unsupported/failed/partial/cancelled are different from a completed check. Never infer “up to date” or “clean” from an empty/error/unparsed response.
- MadClean self-release checking is opt-in and user-triggered. Missing configuration must say “Update checking not configured.” Keep the pinned repository/HTTPS browser-path validation, anonymous no-redirect/no-cookie client, timeout/response bounds, stable-version validation and private/offline failure states. No automatic polling, external reminders, credential embedding, asset downloads, self-installation or restarts. Preserve confirmed session reminders through failed rechecks, with honest timestamps.
- Production uses real Windows data. Any future design/sample mode must be visibly marked everywhere it is active.
- Never persist raw provider output, full startup commands, detection resource paths or secrets in activity logs. Do not add telemetry or remote inventory upload without explicit user authorization.
- Disk maps are metadata-only selected-local-folder views of known logical bytes. Skipped/unknown sizes must remain incomplete; never imply physical allocation, safe deletion or speed/repair improvements. Installed-app inventory must not use Win32_Product, read/execute raw uninstall commands, or force-delete applications. Leftover comparisons require complete in-session snapshots, probe only prior validated local install paths, and label results as candidates rather than junk. No profile/AppData sweeps or automatic shared-dependency/data/save/settings removal. Selected leftover-file previews refresh actual registrations again, validate an exact typed prior-install-root scope, block known overlaps/protected roots, and read bounded guarded metadata only. Do not read file contents, infer inactive use from attribute handles, label remaining files junk, or reuse this scope as action authorization.
- The user authorized continued implementation of the roadmap. Implement Windows Diagnostics in the stages defined in docs/WINDOWS-DIAGNOSTICS.md, preserving the passive discovery foundation. Never attach SFC/DISM/repair commands to ordinary inventory or infer health from missing events. Each finding requires source/time range/coverage/uncertainty/impact. Recheck current official Microsoft command semantics before any future tool implementation; repairs require explicit selected actions, elevation consent, safe cancellation/status and actual result logs. No arbitrary DLL downloads, scalar health scores or performance promises. Do not reuse the metadata-query process-tree kill runner for servicing repairs.
- System-tool version identity must come from the bounded embedded VERSIONINFO reader on the same signature-qualified held executable stream. Do not restore FileVersionInfo/path/MUI lookups, alternate-name allowances or loader-based resource reads. Every present original filename must match the exact selected basename and numeric versions must agree; missing/conflicting/malformed metadata remains Unknown. A separate raw metadata fixture is not signature trust, Windows integrity or execution permission. Preserve stream ownership/position and fixed enum/count-only diagnostics; see docs/SYSTEM-TOOL-EMBEDDED-VERSION.md.
- The user authorized staged duplicate/shortcut review implementation under docs/FILE-REVIEW-ROADMAP.md. Duplicate proof requires full content verification, not names/size/hash alone; distinguish hard-link aliases, skip reparse/protected/system/application areas by default, and require supported handle-based consistency and protection of a verified independent retained copy through any later selected action, or block it. Shortcut inspection must not activate/search/track/save targets; offline/network/temporary/access-denied cases are unknown, not broken. Later removal is explicitly selected and shortcut-only. Keep these separately invoked modules out of ordinary inspection; discovery does not authorize deletion.
- Selected shortcut rechecks are exact-file reads through the same guarded metadata helper and static STA worker gate as discovery; never implement them by rescanning siblings. Preserve original snapshot/Partial coverage and source-bound selection generations; a current result does not establish original object continuity or removal safety. Caller cancellation must not close worker handles, and success follows worker-owned COM cleanup/gate release. Missing/inaccessible shortcut files are Unknown target evidence. See docs/SHORTCUT-RECHECK.md; its private scope is a read selector, never an action token.
- BIOS/firmware discovery is read-only and explicit: use local projected CIM facts and supported WUA class metadata, never title/date-to-BIOS-version inference. Firmware-reported board Version is not necessarily PCB revision. Keep installed BIOS identity, WUA package metadata and manufacturer-verified model/revision/version sources separate. OEM firmware overrides any retail-board resemblance; unidentified/unsupported/offline/ambiguous sources never become Up to date. Guides must be allowlisted official pages, with vendor power/recovery-key prerequisites and their uncertainty disclosed. No firmware assets, flashes, installs, encryption changes, restarts or purchases. Hardware Upgrades H1 is an explicit local read-only allowlisted CIM inventory under docs/HARDWARE-UPGRADES.md; manufacturer specifications and advice remain queued. Never collect serial/UUID/service-tag identifiers or infer PSU/connectors/clearance/free slots/soldered-memory upgradeability or manufacture compatibility advice.
- Later mutations require exact previews and explicit user intent. Restore points cannot restore deleted files. No registry cleaner, bulk drivers, forced restarts or silent elevation.
