# Structured WinGet discovery candidate

The isolated `MadClean.Windows.WinGet` library is an explicit read-only candidate, not the production application's update adapter. It consumes the pinned prebuilt ComInterop 1.10.340 projection and normal C#/WinRT runtime. Existing text-based production discovery remains unchanged until actual Windows and packaged-query qualification. Linux policy tests cannot qualify activation, authentication, source connection, cancellation, or published loading.

`StructuredWingetInventory.ReadObservedAsync(token)` performs no constructor/startup work. It registers one process-wide pending owner before scheduling a dedicated thread, initializes MTA on that thread, and balances that initialization there. Fixed direct COM activation requests only LOCAL_SERVER | NO_CODE_DOWNLOAD and IInspectable. The factory has exactly four private call sites: PackageManager, FindPackagesOptions, CreateCompositePackageCatalogOptions and AuthenticationArguments. Their production CLSIDs are taken from Microsoft's [exact-release public header](https://github.com/microsoft/winget-cli/blob/v1.10.340/src/Microsoft.Management.Deployment/Public/ComClsids.h). It never uses the SDK default factories, manual RPC fallback, registration repair, engine installation, elevation, or a user-supplied CLSID. Public `WinRT.MarshalInspectable<T>.FromAbi` wraps each acquired pointer; `DisposeAbi` balances only that original acquired reference in `finally`. Runtime-cached wrappers are not force-released.

Before any connection, the one existing non-composite `winget` reference must have the exact documented name/type/argument/identifier tuple, AcceptSourceAgreements set and read back false, and known AuthenticationType.None. Missing interfaces, unknown authentication, altered source metadata or failed controls refuse before connection. Per-reference background update interval is set and read back zero. Authentication arguments are explicitly Silent, with no account, and read back. No sources, global settings, accounts, agreements or credentials are changed. A composite includes only that reference and uses LocalCatalogs installed-first search. Catalog opening can fetch metadata and write WinGet-managed caches/logs; interval zero does not prove data freshness.

Actual successful Connect and Find status values are required. Find requests at most 256 matches and preserves native truncation, local projection cap, failed properties and duplicate-correlation ambiguity. Only bounded display name, identifier, installed version, provider update Boolean, default offered version and its catalog source tuple are projected. No installation paths, uninstall commands, metadata methods, installer/applicability checks, actions, or unordered AvailableVersions selection are used.

An Available row means **WinGet reports a newer version** and usable installed/default-version/source facts were observed. The default version is the provider's default choice, not independently verified as newer, compatible, secure, installable or unpinned. No local numeric/lexical version comparison is performed. False/missing update flags and absent/ambiguous correlation remain Unknown; an empty successful query never means all installed software is up to date. Partial coverage is retained separately from positive per-row observations. Package identities are local result data, never diagnostic fields or activity-log output.

Caller cancellation and the 90-second caller deadline stop waiting and latch a stop request. They do not cancel/dispose a pending SDK operation, terminate a client/server, or prove provider work stopped. The same registered owner retains projected objects and actual Connect/Find operations until their real task completion, checks the stop latch between operations/rows, then uninitializes MTA. `HasPendingNativeRead` remains true until actual worker cleanup; a second query is refused while pending. No forced GC, FinalReleaseComObject, private RCW disposal or zero-server-reference claim is made. Normal runtime-managed wrapper lifetime remains independent from finishing a client query.

`StructuredWingetObservation` separates the local result rows from a closed diagnostic (stage, outcome, nullable HRESULT, attempt/completion times, bounded counts and nullable control observations). Interrupted observations may have no CompletedUtc while the worker remains pending. Completion timestamps describe the client worker, not catalog data age or all provider background work. Diagnostics contain no raw provider errors, package names/identifiers, paths or credentials.

Portable tests cover altered sources, unknown agreement/authentication controls, missing/unknown versions, provider-only ordering, false update flags, ambiguous duplicate IDs, bounds, property failures and empty results. Remaining gates include actual missing/available registration, source control support, real Connect/Find outcomes, caller interruption with pending ownership, and the actual published runtime/projection layout. Production application wiring remains unchanged pending those gates.
