# Real hardware inventory UI qualification

H1 remains an explicit local read-only query of fixed Windows CIM properties. It does not contact manufacturers, purchase parts, install software, change firmware, request elevation, or infer compatibility. The existing source-only metadata contract passed; this increment adds actual populated App selection and refresh validation. No sample rows or provider injection are used.

The App retains a read-only copy of the accepted response container with the exact fact objects, separately exposing UTC shared query-attempt and response-receipt times. Neither is a per-class observation or completion time. Unknown and Partial remain unchanged. Starting a new read clears current response, selection and manufacturer guidance. Cancellation/failure leaves no stale current response. Selecting a fact requires its reference to belong to the current snapshot.

The actual adapter task is retained before awaiting it. Overlapping reads and window closure remain blocked until that query task finishes. Normal cancellation may terminate only the owned read-only metadata child process, according to the existing query runner; it must never be reused as cancellation for SFC/DISM or another servicing client. Actual query/stream completion does not establish that every underlying CIM service stopped. Unexpected dispatcher shutdown retains the CLR until the actual task finishes, without waiting on a stale UI busy flag or repeating layout work.

The standard reportv6 requires `ui-hardware-inventory-interaction` before claiming a passed v6 report; exact versions1–5 keep their existing requirements. After all screenshots, the helper invokes the normal hardware button, accepts only a genuine populated Available/Partial response, verifies actual typed receipt/bindings/allowlisted rows, selects a real grid item and compares its rendered details. It then invokes a second real refresh, observes clearing, validates the new query/snapshot, and verifies a prior genuine row cannot become selected again. No values, component identities, provider output or loaded-data screenshots are exported. Fixed counts and booleans describe only observed coverage.

Manufacturer-source eligibility is independently derived from actual complete unique PC metadata. No online source query is invoked by this test. Missing/ambiguous/unmatched hardware does not become a supported Surface identity. Runtime Unknown/Failed/empty results stay inconclusive; a successful interaction does not establish accurate hardware values, physical free slots, soldered-memory replaceability, PSU/connectors, clearance, supported RAM/CPU/storage limits or upgrade recommendations. Hosted VM facts remain virtual provider observations, not physical-PC compatibility evidence.

New source-matched Windows evidence is required for this interaction. Timed cancellation/error races, physical keyboard/screen-reader input, DPI and actual OEM-machine comparison remain separate validation work.
