# Research: structured WinGet discovery

Research only, 2026-11-03. No provider query, source agreement acceptance, package/module/runtime installation, registration repair or Windows action ran. No dependency or adapter is added. The existing text parser's HeaderNotRecognized result remains Unknown; this research neither identifies its cause nor relaxes its acceptance rules.

## Supported route and source evidence

Microsoft publishes a structured Windows Runtime/COM API in [PackageManager.idl](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment/PackageManager.idl). Research read official source commit **557abb5c23208b89ad3b6aab725378dc8d1f727f**. Source contract numbers are API contracts, not App Installer marketing versions; presence of winget.exe does not prove these interfaces are available.

The official [minimal out-of-process C# sample](https://github.com/microsoft/winget-cli/tree/557abb5c23208b89ad3b6aab725378dc8d1f727f/samples/MinimalCallers/C%23/WinGet-OutOfProc) uses Microsoft.WindowsPackageManager.ComInterop 1.10.340, Microsoft.Windows.CsWinRT 2.2.0, net10.0-windows10.0.22000.0 and explicit x64/ARM64/x86 platforms. It constructs PackageManager, gets InstalledPackages, connects and checks status, then FindPackages with empty options. That establishes a maintained C# route without installing a PowerShell module. It is a sample, not a safe-to-copy MadClean policy implementation.

Research inspected that NuGet version's ZIP metadata/build assets only. It contains a managed net8.0-windows10.0.22000 projection, WinMD and architecture-specific native factory shims; it declares no package dependencies. Static factory linkage is the default and AnyCPU without an architecture is rejected by its targets. Shipping the projection/shim is a deliberate build dependency, not installation of the WinGet engine. The sample target and inspected package assets do not establish support for every Windows 10 build. A proposed first adapter can explicitly require Windows 11 build 22000+ and a qualified existing App Installer, retaining Unsupported on older systems. Do not claim the sample's package matches every detail of current master: audit the chosen pinned release's activation and contract behavior before adoption.

## Activation is not bootstrap permission

The sample's new PackageManager() reaches the [out-of-process factory](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment.OutOfProc/Factory.cpp). It first activates CLSCTX_LOCAL_SERVER | CLSCTX_NO_CODE_DOWNLOAD. **For an administrator caller receiving REGDB_E_CLASSNOTREG, it falls through to WinGetServerManualActivation_CreateInstance.** Therefore it is incorrect to describe this constructor unconditionally as simple existing-registration-only activation.

Tracing the official [manual activation client](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/WinGetServer/WinGetServerManualActivation_Client.cpp) establishes that production code resolves the existing Microsoft.DesktopAppInstaller_8wekyb3d8bbwe package through Windows package APIs, finds WindowsPackageManagerServer.exe, and may CreateProcess it with --manualActivation under the existing caller. It then connects over local RPC. The inspected path does not download/install/register a package, request runas or change identity. Missing package/files fail. Consequently inherited administrator status alone is **not** a reason to block this official activation path. Starting an already installed server differs from bootstrapping/installing a runtime. A candidate must audit the exact pinned release's implementation and production build configuration; these current-source facts do not authenticate an arbitrary copy of a server or prove an older package behaves identically. Preserve actual activation/capability failures as Unavailable; no registration repair, engine download, identity switch, elevation request or custom activation fallback is authorized.

The separate official source [LocalServerInstanceInitializer](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment.Projection/Initializers/LocalServerInstanceInitializer.cs) uses direct CoCreateInstance and has AllowLowerTrustRegistration and UseDevClsids default false. Its enclosing projection project references WinGet SharedLib/group-policy code; it is not the same ready-made public package path as the minimal sample. Do not copy that source, enable lower-trust registration, choose development CLSIDs or introduce bootstrap/repair helpers merely to overcome an unavailable client. Packaged/unpackaged caller identity and capability decisions remain actual service outcomes: Connect checks PackageQuery capability; neither elevation nor a guessed capability bypass is a recovery strategy.

## Agreements and authentication: mandatory pre-connect policy

The source [PackageCatalogReference.h](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment/PackageCatalogReference.h) initializes **AcceptSourceAgreements=true**. Contract **6** adds SourceAgreements and AcceptSourceAgreements. Before **every** direct Connect/ConnectAsync, and before connecting a composite, require actual support for this interface/property and set **AcceptSourceAgreements=false on every non-composite reference**. The composite setter is unsupported; configuring only the composite is insufficient. Older/unknown property support is Unsupported before Connect, never a retry with defaults.

[Connect implementation](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment/PackageCatalogReference.cpp) returns SourceAgreementsNotAccepted when false and required agreements are present, before source.Open. Report that outcome without prompting acceptance or silently changing source state. Even a pre-existing accepted source is not permission to set this property true.

Contract 10 provides AuthenticationInfo/AuthenticationArguments. [Converters.cpp](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment/Converters.cpp) defaults COM authentication to Silent; explicitly setting AuthenticationMode.Silent is clearer when supported. Never use Interactive/SilentPreferred, credentials, accounts or an auth prompt. A narrow first adapter should require contract-10 metadata and reject authentication-required/unknown source types before connection, rather than rely on silent cached identity. A configured source's name alone does not establish its trusted URL/type/origin. Inspect bounded structured Info and allow only the explicitly supported official source identity; do not add/reset/edit sources or assume a custom source named winget is Microsoft's source.

## Concrete inventory/update contract

Use separate local inventory and user-initiated online discovery:

1. Activate the fixed production out-of-process PackageManager under the current caller through the audited official existing-component activation path. Use GetLocalPackageCatalog(InstalledPackages) for local inventory, with the pre-connect policy above. Keep results separate from existing ARP/Appx counts; these inventories overlap and are not unique app totals.
2. For online discovery, resolve only an already configured supported official catalog using structured catalog references. Create a composite with that reference and CompositeSearchBehavior.LocalCatalogs. The converter maps this to repository Installed behavior; Connect combines it with the installed source, permitting installed-first correlation with available versions. Do not pass the entire unreviewed source list or search all remote packages.
3. Require ConnectResult.Status==Ok and a usable catalog; then require FindPackagesResult.Status==Ok. Set a bounded ResultLimit, preserve WasLimitExceeded and project bounded fields. The public IDL has no continuation token: truncation remains Partial, not a complete installed or update baseline. Preserve per-property exceptions/unknowns rather than letting one inaccessible package imply zero updates.
4. Read CatalogPackage.InstalledVersion, available version identifiers, DefaultInstallVersion and IsUpdateAvailable as independent observed facts. AvailableVersions ordering is explicitly **not guaranteed**; never choose its first element as latest. Use the provider's version/comparison semantics, not System.Version or lexical guessing.
5. Display true as **WinGet reports an applicable update**, with source and last-check time. Display false as **No applicable update reported by this catalog**, with coverage limits. Missing correlation/installed version/source coverage, uncertain comparison, failure, offline operation or truncation stays Unknown/Partial. Never mark unchecked applications Up to date.

The [CatalogPackage implementation](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/Microsoft.Management.Deployment/CatalogPackage.cpp) derives IsUpdateAvailable and DefaultInstallVersion from [GetLatestApplicableVersion](https://github.com/microsoft/winget-cli/blob/557abb5c23208b89ad3b6aab725378dc8d1f727f/src/AppInstallerRepositoryCore/PackageVersionSelection.cpp). That algorithm opens pin data read-only, considers pins, filters installed source/channel, checks provider version ordering and installer applicability, and can yield no candidate when a newer version exists but is pinned or inapplicable. Thus false is not proof the installed version is newest or secure; a null DefaultInstallVersion is not proof no software update exists. Do not ignore pins to make a candidate appear.

Connecting remote catalogs may download/refresh metadata and write provider-owned cache/log state. Contract 8's PackageCatalogBackgroundUpdateInterval can disable background checks at zero, but a cached result is not a fresh check and source.Open can still require external metadata. Do not use InstalledPackageInformationOnly (contract 9) as a fresh available-update query: it explicitly limits to installed-source information without external resources. Record actual check time separately from unknown catalog-data age. No Install/Upgrade/Download/Uninstall/Repair/Add/Remove/Edit catalog methods belong in this adapter.

## Finite validation before adopting a dependency

Audit one exact stable ComInterop version and its published source/tag; verify runtime interface support rather than equating NuGet presence with installed server capability. Add portable typed-projection policy tests for missing agreement control, authentication unknown, failed connect/find, truncation, missing version, false update with pins and partial row properties. Then use the existing separate disposable update-discovery stage to qualify packaged output against already installed App Installer under recorded current-caller conditions, including the distinct inherited-admin activation route if supported, with no bootstrap, agreements, installations or source edits. Preserve async COM ownership through cancellation; request cancellation is not proof a service/background metadata operation stopped, and never kill a shared WinGet server.

Only after those checks should this become the primary structured adapter. Keep the old text observation honestly Unknown during transition; no parser fallback or diagnostic-label rewrite is justified by this research. No Windows activation, runtime behavior, network-source coverage or executable packaging has been validated by reading source on Linux.
