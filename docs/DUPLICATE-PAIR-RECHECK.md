# Fresh comparison of a selected duplicate pair

Duplicate review now has a separate **Recheck selected pair** action after the snapshot worksheet. It reads exactly the candidate and retained entry you selected, without enumerating sibling files or changing the historical inventory. Ordinary Inspect never invokes it. There is no removal handler; `CanRemove` remains get-only false.

The scope factory reuses the snapshot worksheet's exact-reference, group, typed-evidence, link-count and observation checks. Both paths must be canonical descendants of one explicit local folder, with distinct original identities and one reported hard link each. Current scope validation supports paths up to 258 characters, 64 MiB per file and a two-minute selected-scope lifetime. Unsupported paths or stale/ambiguous selections are rejected before a new read.

Windows refreshes actual known-folder and registered-application exclusions before opening either file. Unresolved essential known-folder exclusions block the new content read. Incomplete optional application-location registrations remain Partial, independently of historical snapshot coverage, while every successfully established protected root remains excluded. The UI displays this current coverage and ownership uncertainty outside the detailed report. Unknown application ownership never becomes permission. The shared registration reader uses fixed-capacity key enumeration and whitelisted InstallLocation values, replacing the duplicate scanner's legacy unbounded name/value calls. It never reads uninstall commands, expands environment tokens or accepts unresolved/device/ADS paths as complete protection evidence.

The portable engine opens exactly two simultaneous guarded content handles, checks current identity, length and single-link evidence, and performs a full byte comparison. Similar names, equal lengths or hashes alone are insufficient. Short reads are filled; EOF, current native stamps and read stability are checked before accepting equality or difference. Content reads are capped at 128 MiB total across both streams and a cooperative 15-second budget. At the exact byte cap, held stream lengths/positions and stable stamps replace a speculative extra-byte probe. Buffers are cleared and both handles closed before publication.

Equal and Different describe the current comparison, retaining Partial if either historical snapshot coverage or current optional application exclusions are incomplete. Changed means identity, size or stability differed; Unknown covers unavailable/aliased/multi-link/unsupported/incomplete data. Matching identity values do not prove uninterrupted object history. Original entries contain no full historical stamps or content digest, so even current Equal does not prove the original bytes were never changed.

Discovery and pair reads now share one process-wide worker across service instances. A 45-second caller wait or cancellation requests that worker stop; it never closes its handles from the caller or permits overlapping work. Cancellation is checked before publication and again after the caller wait. The development fixture retains its entire owned tree while any duplicate worker is pending.

The UI starts with empty choices and no current result. Selection, Clear, folder or snapshot changes invalidate the current report; exact reference/root/generation guards discard late results. It shows separate historical/current evidence, comparison times and actual bytes read across both streams. That byte count is neither physical allocation nor reclaimable space. No keeper lease survives the report, and ownership, inactivity and removal safety remain unknown. Paths and identities do not enter the activity log; it records only the fixed DuplicatePairRecheck area, outcome and time.

The owned Windows fixture uses a real source scan and two independent test files. It checks current equality, then a single owned tail-byte change producing current Different through the same historical scope, hard-link rejection, pre-cancellation, unchanged retained/control files and unchanged history. The fixture never injects rows into the UI. The separate initial panel capture is query-free; it cannot establish populated selection/cancellation behavior.
