# In-session evidence from independent sources

The Windows Diagnostics panel combines already-collected observations from five independent sources: caller-visible storage capacity, Defender status, recorded component-store flags, a fresh component-store scan and the fixed SFC client. It makes no overall PC-health score or combined healthy verdict. Reading/selecting the panel starts no query, scan or action.

Storage/Defender update only when ordinary Inspect collects them. DISM/SFC update only after their own existing explicit confirmation flows; inspection never invokes those operations. A new request replaces only its source row with pending evidence. Other source histories remain independent. Failure/stop does not leave an earlier healthy-looking row current. Selected rows must belong by reference to the current list; a replaced selected area receives its new current row.

Pure Core projections consume the actual immutable intent and already-assessed result. They validate request ID, kind, enum domains, UTC times, transport/source consistency and the existing assessment again. The original non-Available state cannot be promoted merely because a retained payload says Healthy. No raw provider Message, executable identity, PID, hash or paths are copied into this report. Fixed source descriptions, collection times, minimized observations, coverage, uncertainty, impact and next step remain visible.

A recorded CheckHealth flag is not a fresh scan or the previous flag's timestamp. A ScanHealth finding concerns only that component-store invocation, not protected system files, every crash or whole-PC health. Every SFC numeric exit remains client evidence with protected-file integrity Unknown, even when streams and ownership settled. Unavailable, malformed, interrupted or mismatched evidence keeps current assessment Unknown. No repair, DLL download, performance promise, automatic recommendation or extra permission is added.

Ordinary-inspection UI checks retain their two-source lifecycle assertions while verifying all three integrity rows remain untouched and unattempted. Existing explicit DISM/SFC UI qualification jobs additionally select the actual callback-produced session row after the original operation and check its source/state/times, rendered read-only details and unchanged activity. They invoke no second operation for the report. Existing report schemas stay unchanged; only fresh source-bound execution can establish these new result-rendering assertions. Older qualified UI runs are not substituted for this increment.

The panel stores in-memory session history only. Rows have different independent collection times and are not live monitoring or a crash-recovery journal. Windows log attribution, protected-file interpretation, physical hardware health and future selected repair validation remain separate work.
