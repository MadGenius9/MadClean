# Hardware upgrade prerequisites — planning only

The Hardware Upgrades page has a separate in-memory prerequisite worksheet. Choose RAM, CPU, GPU or storage, enter your own budget, currency, region and use case, then choose **Review prerequisites**. No default preference is inferred from Windows, location or installed components. Budget uses plain digits with an optional decimal point and at most two decimal places; grouping, currency symbols, signs and exponent notation are rejected. Currency/region use supported three-letter currency and two-letter region codes.

The worksheet lists the existing compatibility policy's evidence requirements for the chosen area. Every requirement and the overall compatibility state stay **Unknown**. It has no manufacturer-specification adapter, product candidate, recommendation, price lookup, shopping link, verification checkbox or action capability. Valid preferences cannot satisfy a missing compatibility check. An invalid or absent area cannot yield an empty successful checklist.

RAM review requires exact manufacturer limits/types/population rules, replaceability and physical occupancy. CPU review requires exact supported CPU and BIOS prerequisites, power/cooling and replaceability. GPU review requires expansion wiring/lanes, actual PSU/connectors, clearance and occupancy. Storage review requires protocol/socket, lane sharing, occupancy, mounting and cooling. Exact OEM model/SKU or retail board/independently verified PCB revision is required in every area. Detected facts and family-level service notes cannot satisfy these requirements.

This is a generic planning checklist, not a report matched to the currently detected PC or a claim that an upgrade is possible. Manufacturer authenticity/content, applicability, conflicting evidence, firmware prerequisites and physical checks remain separate gates. Do not infer soldered-memory upgradeability, PSU capacity, case clearance, spare ports/slots or supported maxima from reported hardware counts or names.

Reviewing, editing and clearing the worksheet starts no query, opens no website, writes no settings/activity entry and changes no hardware or Windows state. Input edits invalidate the old worksheet; **Clear planning inputs** clears the entries. Inputs remain only in the app session. The Core report contains fixed explanations and requirement descriptions, never copies the arbitrary budget/use-case text into its output. There is no persisted/exported plan or approval record.

Portable validation covers malformed/localized/overflow budgets, unsupported or missing areas, bounded preferences, privacy and the inability of complete preferences to produce compatibility. WPF bindings, keyboard interaction, scaling, invalidation and Clear still require a real Windows run. GitHub pushes are paused, so local compilation is not a new remote CI result. Use the [home-test checklist](HOME-TEST-CHECKLIST.md) for an observational first pass.
