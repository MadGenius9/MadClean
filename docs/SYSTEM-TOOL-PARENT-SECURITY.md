# Owned private-parent structural security preflight

This development-only prerequisite composes the existing strict journal security predicate with the existing relative-directory creation control. It does not enable the production journal writer or any operation, inspect user-profile security, repair permissions, elevate or execute DISM/SFC/installers.

The single existing `RelativeDirectoryCreateProbe` worker validates and retains its marked GUID fixture root, marker and ancestor handles. Under that exact owned root it creates three fresh fixed-name parent directories, each with an explicit creation descriptor: a protected current-user/SYSTEM two-allow-ACE descriptor; an unprotected descriptor; and a protected descriptor with an additional Everyone child-directory-create grant. No pre-existing parent is overwritten or repaired. The fresh unprotected negative-case parent alone is subsequently configured as described below; no real user-profile security is changed. The native control accepts only the original GUID root or the exact fixed `relative-parent-qualified` child, never an arbitrary parent or descendant.

Each parent is opened no-follow with READ_CONTROL and attributes access. A temporary non-owning `SafeFileHandle` borrows the existing guard under DangerousAddRef solely for `SystemToolJournalStore.VerifyPrivateSecurity`; there is no duplicated ACL decoder. That existing method requires the exact current-user owner, protected DACL, two prescribed noncallback allow ACEs and exact directory inheritance/full-access masks. It is deliberately conservative structural qualification, **not effective-access analysis**. Account names, SID/ACE bytes and paths are not exported.

The unprotected negative case is established from returned Windows state rather than from omitted SDDL syntax. The harness observes `SE_DACL_PROTECTED` through `GetSecurityInfo` plus `GetSecurityDescriptorControl` on the held newly-created parent, then uses `SetSecurityInfo(DACL_SECURITY_INFORMATION | UNPROTECTED_DACL_SECURITY_INFORMATION)` on that exact handle and independently reads the control flags again. Only this fixed fresh owned case requests WRITE_DAC; the general open helper is unchanged. The setter receives the creation descriptor's verified present, non-NULL DACL. Its DWORD return code is checked directly. Descriptor-copy allocations must be released successfully before the next native call; uncertainty retains the whole worker. No production permission setter or action is added.

Before/after control flags, setter invocation/result and refusal state remain unobserved until actually returned. Setup failure or a still-protected postcondition is Unknown and cannot reach composed creation. A successful setter alone does not establish setup. Once an actual unprotected descriptor is observed, acceptance by the unchanged strict predicate remains a failed invariant. Unprotecting can merge inherited ACEs, so refusal is not attributed solely to the protection bit. The actual unprotected and extra-grant parents must be refused by that predicate. Their composed native creation routes are not invoked and a bounded independent topology observation must still show each parent empty. Invocation counts describe this composed route only; they are not an instrumented trace proving that every possible child I/O API was absent. Only the qualified parent reaches one actual native baseline invocation: relative CREATE_NEW, held parent/object identity checks, requested descriptor observation, collision refusal, exact-handle disposition, checked native release and independently observed child absence. No by-name deletion fallback is added. Parent directories remain owned until the enclosing fixture's existing checked teardown.

A verifier cleanup failure is checked even when its original typed security rejection is caught: uncertain LocalFree blocks subsequent allocations, cases and native control. Creation descriptors, borrowed handles, parent guards and module state remain worker-owned. Caller interruption never closes or retries them. An incomplete/uncertain native return retains the entire exact fixture scope. Preflight Pass additionally requires actual outer worker teardown, no pending worker, no retention flag and no global journal descriptor uncertainty. Native-control cleanup and whole-worker ownership release are reported separately.

## Official semantics checked

On 2026-11-03 the current official Microsoft SDK API sources were retrieved successfully and read:

- [GetSecurityInfo](https://learn.microsoft.com/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/aclapi/nf-aclapi-getsecurityinfo.md)): handle-based descriptor copy, READ_CONTROL for owner/DACL, LocalFree ownership, and documented concurrent-security-change limitations.
- [GetSecurityDescriptorControl](https://learn.microsoft.com/windows/win32/api/securitybaseapi/nf-securitybaseapi-getsecuritydescriptorcontrol) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/securitybaseapi/nf-securitybaseapi-getsecuritydescriptorcontrol.md)): control/revision metadata, not a permission evaluation.
- [CreateDirectoryW](https://learn.microsoft.com/windows/win32/api/fileapi/nf-fileapi-createdirectoryw) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/fileapi/nf-fileapi-createdirectoryw.md)): explicit creation descriptors versus inherited defaults, existing-name refusal and filesystem security support. Actual returned security is independently checked; a requested descriptor is not presumed applied.

Additional official SDK API sources retrieved and read on 2026-11-03:

- [SetSecurityInfo](https://learn.microsoft.com/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/aclapi/nf-aclapi-setsecurityinfo.md)): DACL changes require appropriate handle access, return a Win32 DWORD status directly, and can propagate inheritable ACEs. A NULL DACL would grant access to everyone and is explicitly rejected by this fixture.
- [GetSecurityDescriptorDacl](https://learn.microsoft.com/windows/win32/api/securitybaseapi/nf-securitybaseapi-getsecuritydescriptordacl) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/securitybaseapi/nf-securitybaseapi-getsecuritydescriptordacl.md)): present and non-NULL are independent checks; the returned DACL pointer belongs to its held descriptor.
