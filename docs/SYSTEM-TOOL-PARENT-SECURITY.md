# Owned private-parent structural security preflight

This development-only prerequisite composes the existing strict journal security predicate with the existing relative-directory creation control. It does not enable the production journal writer or any operation, inspect user-profile security, repair permissions, elevate or execute DISM/SFC/installers.

The single existing `RelativeDirectoryCreateProbe` worker validates and retains its marked GUID fixture root, marker and ancestor handles. Under that exact owned root it creates three fresh fixed-name parent directories, each with an explicit creation descriptor: a protected current-user/SYSTEM two-allow-ACE descriptor; an unprotected descriptor; and a protected descriptor with an additional Everyone child-directory-create grant. No existing parent is overwritten or repaired. The native control accepts only the original GUID root or the exact fixed `relative-parent-qualified` child, never an arbitrary parent or descendant.

Each parent is opened no-follow with READ_CONTROL and attributes access. A temporary non-owning `SafeFileHandle` borrows the existing guard under DangerousAddRef solely for `SystemToolJournalStore.VerifyPrivateSecurity`; there is no duplicated ACL decoder. That existing method requires the exact current-user owner, protected DACL, two prescribed noncallback allow ACEs and exact directory inheritance/full-access masks. It is deliberately conservative structural qualification, **not effective-access analysis**. Account names, SID/ACE bytes and paths are not exported.

The actual unprotected and extra-grant parents must be refused by that predicate. Their composed native creation routes are not invoked and a bounded independent topology observation must still show each parent empty. Invocation counts describe this composed route only; they are not an instrumented trace proving that every possible child I/O API was absent. Only the qualified parent reaches one actual native baseline invocation: relative CREATE_NEW, held parent/object identity checks, requested descriptor observation, collision refusal, exact-handle disposition, checked native release and independently observed child absence. No by-name deletion fallback is added. Parent directories remain owned until the enclosing fixture's existing checked teardown.

A verifier cleanup failure is checked even when its original typed security rejection is caught: uncertain LocalFree blocks subsequent allocations, cases and native control. Creation descriptors, borrowed handles, parent guards and module state remain worker-owned. Caller interruption never closes or retries them. An incomplete/uncertain native return retains the entire exact fixture scope. Preflight Pass additionally requires actual outer worker teardown, no pending worker, no retention flag and no global journal descriptor uncertainty. Native-control cleanup and whole-worker ownership release are reported separately.

## Official semantics checked

On 2026-11-03 the current official Microsoft SDK API sources were retrieved successfully and read:

- [GetSecurityInfo](https://learn.microsoft.com/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/aclapi/nf-aclapi-getsecurityinfo.md)): handle-based descriptor copy, READ_CONTROL for owner/DACL, LocalFree ownership, and documented concurrent-security-change limitations.
- [GetSecurityDescriptorControl](https://learn.microsoft.com/windows/win32/api/securitybaseapi/nf-securitybaseapi-getsecuritydescriptorcontrol) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/securitybaseapi/nf-securitybaseapi-getsecuritydescriptorcontrol.md)): control/revision metadata, not a permission evaluation.
- [CreateDirectoryW](https://learn.microsoft.com/windows/win32/api/fileapi/nf-fileapi-createdirectoryw) ([consulted source](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/fileapi/nf-fileapi-createdirectoryw.md)): explicit creation descriptors versus inherited defaults, existing-name refusal and filesystem security support. Actual returned security is independently checked; a requested descriptor is not presumed applied.

## Claim ceiling and validation

This is one necessary owned composition contract. It does not establish foreign effective rights, trusted production ancestors, absence of prior handles, namespace-race resistance, durable history, same-user authenticity or permission to create a production journal. The immutable production-creation guard remains false. Linux compilation and evidence-publisher tests are not Windows runtime proof. The required `owned-private-parent-security-preflight` check remains unverified until a matching-source Windows report records the actual predicate, native call and released ownership.
