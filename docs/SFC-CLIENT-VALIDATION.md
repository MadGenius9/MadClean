# Disposable SFC client-lifecycle qualification

This separate development mode requests only the genuine inbox `sfc.exe /verifyonly` on the disposable GitHub Windows runner. The official Microsoft SFC source read on 2026-11-04 explicitly says this scans protected system-file integrity without repairs; the consulted URL/hash and unsupported exit-code/stop mappings are recorded in [the SFC contract](SFC-VERIFICATION.md). Windows may write CBS/diagnostic metadata. No `/scannow`, repair, offline/custom source, elevation request, installation or restart is permitted. It never runs with ordinary inspection or the passive harness.

The normal application uses a reviewed source literal, never an environment/configuration override. The fixed backend qualified before the normal public request candidate was enabled for its own qualification. The private development entry requires a held exact request proof, fixed hosted CI job/repository/branch/event/source/run/attempt context, a fresh GUID-marked scope under this repository's artifacts directory, and already-effective non-impersonated administrator rights. It is an accidental-use development fence, not cryptographic host attestation or a replacement for Windows permissions. Setting a flag does not change the App's public gate.

The harness first verifies actual fixed executable identity through the existing trusted Windows provider. It prepares a fresh Core preview and explicitly confirmed test intent, preserving the original identity expiry. A separate pre-cancelled intent/proof must return Cancelled without worker transfer, admission reservation, administrator/identity queries by the candidate, or client start. Its setup identity/proof checks are not described as absent. It then runs at most one actual client: a new private candidate intent if the normal source guard is false, or the real App selection/identity/preview/acknowledgement/Confirm controls when the reviewed source guard is true. The latter does not call the private candidate entry for its actual client. No retry, alternate executable, mock identity, clock override or parsed provider text is substituted.

Proof ownership transfers after managed owner allocation and shared admission but before worker scheduling. The actual owner retains the original process, both byte-discard tasks, trusted executable leases and marker proof through actual exit/drain/cleanup. Mismatched requests are rejected before queue/native work. Refused transfer releases only unused admission; uncertain transfer/start/cleanup retains the exact proof and blocks cooperating requests. Caller cancellation/timeout does not stop SFC, pipe reads or services. No process is killed.

Stdout/stderr are consumed only by fixed-size raw-byte discard drains; no output text or sensitive values reach CI logs/artifacts. The protected CBS log is only a reference. Actual timestamps and nullable transport observations distinguish unobserved facts from false. The harness keeps the CLR alive through real identity and client/provider pending or retained ownership, including after an invariant exception. There is no local watchdog/forced exit. The thirty-minute disposable job limit is external; expiration is unqualified and not native cancellation or cleanup proof.

The fixed artifact is `MadClean-SFC-client-validation`, containing only `artifacts/sfc-client-validation/report.json`. Its closed version1 schema and separate version2 public/private paths export source/run/timestamps, stage/state, boolean lifecycle facts and an actual nullable client exit code. It exports no PID, executable path/hash/version, provider output or arbitrary exception message. Exact source/context, original identity freshness, pre-cancel proof, matching transferred/released candidate proof on the private path or actual normal-control proof on the public path, actual client start/exit, both completed drains and owned scope cleanup are required. Missing coverage remains inconclusive.

A zero exit is required as this narrow test's normal-client-exit acceptance criterion. It is **not** a documented mapping to successful verification, absence of corruption or whole-PC health. `integrity` must remain `Unknown`, including when lifecycle qualification passes. Nonzero codes remain actual observations with an inconclusive lifecycle outcome. This supplies no scan-result interpretation, timed-stop qualification or blanket production-readiness verdict. Version2 public confirmation proof requires all eight actual UI facts; the old private proof cannot substitute for it.

The publisher treats this as optional independent evidence: it requires a successful source-matched job/download and strictly valid passed report before setting `sfcClientLifecycleQualified`. Invalid/missing evidence cannot suppress unrelated results; failed/cancelled jobs cannot become qualified. Existing passive inconclusive/failure policy is unchanged. No distribution binary or ZIP is uploaded.


## Version2 normal public workflow

Version1 acceptance is unchanged. Version2 adds derived `uiRequired` and a nullable fixed eight-fact `ui` object. With the normal source guard closed, the existing one private candidate runs and private proof remains required. With it enabled, one real public UI request replaces that actual candidate; the private candidate transfer/release fields must be null, while fresh identity/result/drains/cleanup and all actual UI facts remain mandatory. The initial no-dispatch pre-cancel case still uses its own exact proof. This avoids running two sixteen-minute clients in one job. `sfcClientPublicUiQualified` requires this actual public path plus successful source-matched job/download; no flag enables public permission. The actual public cycle passed at source326cda1/evidence71a0f7d3; broader runtime and failure cases remain unverified.
