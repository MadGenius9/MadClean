## Requirements versus stronger engineering goals

The necessary product safeguards remain: genuine Windows data and honest coverage, explicit exact-change selection, protected data, supported mechanisms, no silent elevation/install/restart, retained actual work through caller stop, and no invented success/recovery. Reversible startup behavior, manual duplicate removal preserving a copy, and careful unknown shortcut targets are explicit user requests. Those requirements cannot be waived by calling an action a later phase.

Some stronger proof goals arose during implementation and should be identified rather than silently treated as new user requirements:

- The user did not ask MadClean to resist arbitrary malicious code already running as the same user or administrator. Document trusted principals and the real privacy/authenticity boundary. This does not excuse ordinary namespace races, unsafe ACLs or access to another user's files.
- The user did not require an impossible universal atomic transaction between a filesystem journal and a Windows servicing engine, or a power-loss guarantee on all hardware. A reviewed design can conservatively preserve an unresolved intent across uncertain dispatch/restart and refuse automatic replay. It must not claim exactly-once native execution, rollback or crash durability it cannot prove. Current gates stay closed pending the actual supported design and qualification.
- Freezing every conceivable metadata/policy predicate forever, all-stream physical accounting and universal OEM coverage are stronger goals than the original feature descriptions. Nevertheless, the existing stricter cleanup and action contracts are repository constraints today. A narrower practical design must be explicitly reviewed and documented against the user's protections; this assessment does not silently weaken them.
- A Defender request-submission result can be useful without a clean verdict or cancellation API for an owned engine scan. Label that limited workflow precisely; do not claim completion of scan-result attribution or quarantine support. No scan is authorized by this planning observation.
