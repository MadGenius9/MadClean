# Update Center: Apps, Drivers, BIOS / Firmware

The original phase-one foundation remains read-only. Update Center now separates **Apps**, **Drivers**, and **BIOS / Firmware**; MadClean's own release reminder remains a separate page. This increment adds local identity discovery and firmware-related offer classification, not flashing or a compatibility engine. No purchase, firmware asset download, BIOS update, encryption-setting change, elevation or restart is authorized or implemented.

## Available read-only slice

- Apps retains WinGet matched installed/available package versions and coverage/unknown/error states. Windows software and unclassified update offers remain visible separately.
- Drivers shows configured Windows Update offers. Missing class/version metadata remains unknown; no third-party catalog, bulk replacement or installation is introduced.
- BIOS / Firmware has an explicit **Read BIOS / PC identity** action. It queries local supported CIM properties only: PC manufacturer/model/SKU (`Win32_ComputerSystem`), board manufacturer/product/reported version (`Win32_BaseBoard`), and BIOS manufacturer/SMBIOS BIOS version/reported calendar release date (`Win32_BIOS`). It projects no serial number, UUID, service tag or recovery key. Common OEM/default placeholders and ambiguous/multiple/missing sources remain Unknown with source errors. Valid remaining sources are preserved as Partial.
- The UI labels these values **firmware-reported**, not manufacturer-verified specifications. `Win32_BaseBoard.Version` is not guaranteed to be the PCB revision needed by a vendor's support table; its UI label says revision unverified. Do not replace missing PC identity with the BIOS vendor (such as AMI) or a similarly named board.
- Check updates continues to query the configured Windows Update service. Only supported `IWindowsDriverUpdate.DriverClass` equal to Firmware marks an offer firmware-related. Title keywords do not classify offers. Missing class metadata makes coverage partial; unclassified offers remain visible. Package date comes from `DriverVerDate` and is not the installed BIOS release date.
- The current WUA interface/SDK has **no DriverVerVersion property**. Available BIOS/package version, exact model/revision applicability, verified BIOS release notes and model-specific prerequisites therefore remain Unknown unless a later documented source supplies them. No offer or no returned offers means neither BIOS current nor complete manufacturer coverage. Firmware-class packages can target system **or device** firmware.

Installed reported BIOS version/date, PC/board identifiers, WUA metadata/source, provider description and attempt times are visible/copyable. Provider descriptions are not relabeled manufacturer-verified BIOS release notes. Identity attempts, WUA offer attempts and manufacturer verification status have separate labels. Cancellation/offline/query/parse/access errors never become Up to date. Reading identity is not an online vendor check, and opening a guide is not a successful page retrieval or version comparison.

## Explicit official release-history review

[Surface firmware-history discovery](SURFACE-FIRMWARE-HISTORY.md) is now implemented separately from local identity and WUA. Only the exact supported Surface Laptop 6 for Business 15-inch SKU can request its two pinned official sources; the current SKU row and authored article applicability must both verify that limited family scope. The 2033 13/13.5-inch naming discrepancy stays Unknown without HTTP. The UI shows dated manufacturer notes and nullable explicitly published UEFI package versions, source section and last attempt/retrieval times. A newer driver-only entry is not a newer BIOS. Installed-version comparison, exact device configuration and latest applicable BIOS remain Unknown. Browser review opens only the fixed official history page; no firmware file is fetched.

## Official guidance and current coverage

The offline guide policy accepts only allowlisted exact HTTPS documentation URLs. The initial catalog recognizes exact normalized Microsoft computer OEM identity and a supported Surface-family model, then offers generic Microsoft Surface guidance and Microsoft UEFI power/recovery precautions. It explicitly does **not** identify the exact model/SKU/board revision, select firmware, verify a supported BIOS version or verify model-specific prerequisites. A motherboard or BIOS vendor cannot override the PC OEM.

Only these initial guide sources were freshly verified:

- [Manage Surface driver and firmware updates](https://learn.microsoft.com/en-us/surface/manage-surface-driver-and-firmware-updates), which applies to Surface and links Microsoft's consumer support instructions. Linked consumer-support contents were not fetched; no unverified numeric battery/power threshold is asserted.
- [Microsoft UEFI firmware update user experience](https://learn.microsoft.com/en-us/windows-hardware/drivers/bringup/user-experience-for-uefi-firmware-updates), including not disturbing the system or unplugging power during an update. This is platform guidance, not exact-model approval.

For a recognized Surface PC, the guide says to check the exact model's current AC-power/battery instructions and manufacturer/organization encryption policy. Ensure the applicable device-encryption/BitLocker recovery key is securely accessible before considering a manually reviewed update; MadClean does not request/store a key, suspend protection, change firmware settings or initiate an update. Model-specific power/battery limits, recovery procedures and prerequisites remain unverified until the correct official instructions are read. Do not generalize Surface requirements to another vendor or SKU.

Dell/HP/Lenovo support reads were denied by the cloud proxy. Their current pages, prerequisites and catalogs are **unverified**, so this build offers no guessed vendor guide or update recommendation for those identities. Unknown/unidentified hardware stays Unknown; an identified but unsupported manufacturer remains Unsupported, never current. Research domain additions are saved in the environment draft, which does not itself apply or publish networking changes. This development limit does not establish whether a user's Windows browser can access the OEM.

The explicit browser buttons open only the allowlisted guidance page; they do not fetch firmware assets. No third-party BIOS downloads, silent installers, model-string web searches, retail-board substitution or forced restarts are supplied.

## Incremental manufacturer matching queue

1. Add one reviewed OEM/source adapter at a time after official access/documentation is verified. Match the exact PC OEM model, SKU/submodel and configuration. OEM laptops/prebuilts use **OEM firmware** even if board metadata resembles a retail motherboard. Unknown OEM-vs-retail identity blocks a recommendation.
2. For a genuinely identified retail/custom board, require exact manufacturer/product and hardware/PCB revision from supported evidence or a safe manual check. Do not choose a close spelling, family member, different revision or retail BIOS for an OEM system.
3. Verify official source and exact model/revision applicability before displaying an available version as matched. Record canonical URL, retrieval/last-check time, installed version namespace, available version, release notes, prerequisites, required intermediate updates, OS/architecture and recovery/power/encryption conditions where applicable. Vendor-specific version ordering is required; dates/title fragments/ordinary numeric comparison are not generic BIOS version rules. Ambiguous comparisons stay Unknown.
4. Missing coverage, offline/changed/auth-required sources, inaccessible pages, unidentified hardware and incomplete or contradictory model/revision evidence stay Unknown/Unsupported with reasons. A fresh attempt time is not evidence of a successful match or Up to date. Windows Update applicability is not a substitute for a manufacturer CPU-support/BIOS table.
5. Initial implementations remain **official guided links only**, with no bundled firmware, automated flashing, purchases or silent settings/restart actions. A future request for firmware execution needs a separate explicit authorization and Windows-specific safety review; it is not authorized by this increment.

## Official Microsoft contracts checked

- [Win32_ComputerSystem](https://learn.microsoft.com/windows/win32/cimwin32prov/win32-computersystem), [Win32_BaseBoard](https://learn.microsoft.com/windows/win32/cimwin32prov/win32-baseboard), [Win32_BIOS](https://learn.microsoft.com/windows/win32/cimwin32prov/win32-bios): read-only firmware-reported identity and CIM release date.
- [IWindowsDriverUpdate](https://learn.microsoft.com/windows/win32/api/wuapi/nn-wuapi-iwindowsdriverupdate), [DriverClass](https://learn.microsoft.com/windows/win32/api/wuapi/nf-wuapi-iwindowsdriverupdate-get_driverclass), [DriverVerDate](https://learn.microsoft.com/windows/win32/api/wuapi/nf-wuapi-iwindowsdriverupdate-get_driververdate), and the official [wuapi.h SDK header](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/wuapi.h): supported classification/date metadata, no DriverVerVersion contract.
- Microsoft's [UEFI firmware update platform](https://learn.microsoft.com/windows-hardware/drivers/bringup/windows-uefi-firmware-update-platform) and [device setup classes](https://learn.microsoft.com/windows-hardware/drivers/install/system-defined-device-setup-classes-available-to-vendors): system/device firmware delivered as driver packages; firmware-class identification does not prove an exact system BIOS target.

## Validation limits

Portable tests cover placeholders, malformed/ambiguous/partial identity, invariant calendar dates, OEM-vs-board guide routing, trusted links, unsupported vendors/models, and firmware classification without title/version inference. Transport cancellation uses the existing tested bounded runner. Linux builds do not run CIM/WUA/WPF or validate real motherboard identity, OEM support matching or firmware prerequisites. Actual Windows identity/provider/browser/category-layout checks remain required before a runtime claim. Later upgrade inventory/specification/advice gates are separate in [HARDWARE-UPGRADES.md](HARDWARE-UPGRADES.md).
