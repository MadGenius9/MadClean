# Fresh selected cleanup-file metadata

Cleanup now has a separate **Recheck selected file** action. It reads exactly one selected candidate's current native metadata, without reading that file's contents, scanning siblings, deleting anything or granting deletion permission. Ordinary Inspect remains the existing cleanup inventory. Application ownership and active use remain Unknown; `CanDelete` is get-only false.

The selector requires an exact candidate reference and unique path in a bounded completed scan. It freezes exclusions, retains original Partial coverage, supports canonical local Windows paths up to258 characters and recognizes only the two existing temporary-root categories. A completed scan is usable for fifteen minutes and a prepared selector for two minutes. Seven-day age is checked against historical and current modification time. Unsupported unrelated rows do not become query tokens or block an otherwise supported selection. Shared protected-name/extension/sensitive-name predicates preserve scanner behavior.

Windows independently maps the category to actual LocalAppData\Temp or Windows\Temp. It loads the real saved exclusions again, requires the captured/current sets to agree, and checks actual protected known-folder redirects plus protected relative names before opening the selected file. Unresolved protection, changed/unreadable preferences or unsupported roots block acceptance. These configured exclusions are not universal registered/unregistered application ownership evidence.

The adapter requests READ_ATTRIBUTES only for the selected target: no READ_DATA, DELETE, write, ACL-read/write or elevation rights. Ordinary root-to-leaf guards, final-path checks and native bookends observe full volume/128-bit identities, logical size, one link, attributes and creation/write/change times. Current file/root observations must remain consistent during the read; handles close before publication. The earlier inventory has no file identity, so matching path/size/modification time does not prove object continuity or unchanged original contents. A changed size/time can be shown separately as current Partial evidence; recent, unsafe, linked or unstable targets remain unverified.

One process-wide metadata worker owns its cancellation source and handles. The caller waits at most45 seconds; cancellation/deadline never closes worker handles. A pending native call retains its ownership and blocks another worker. Known managed refusals produce fixed actionable messages; actual Win32 codes remain separate and unknown causes are not guessed.

The UI prepares bounded selection policy off the dispatcher, checks its generation before starting native work and again before display. Selection, scan or saved-exclusion changes invalidate current observations. Only a completed scan publishes a new source. Production UI rejects development-source reports. The activity log records only its fixed area/outcome/time; paths, sizes and native identifiers stay out of the log.
