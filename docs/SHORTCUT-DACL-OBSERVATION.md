# Recorded shortcut access-control facts

The existing explicit selected-file evidence read now includes an optional DACL summary. It queries only the same already-open shortcut handle, after protected-folder checks. Ordinary inventory and the metadata-only selected recheck do not invoke it. There is no account lookup, effective-access calculation, security change or action enablement.

`GENERIC_READ` for files already maps `READ_CONTROL`. The reader requests no additional access and calls `GetSecurityInfo` with `SE_FILE_OBJECT` and `DACL_SECURITY_INFORMATION` only. Owner, group, SACL and separate DACL output pointers are NULL; the returned security descriptor is inspected in memory and released with `LocalFree`. The API chooses its allocation size. A 128 KiB inspection cap applies after allocation, rather than pretending that the caller can pre-bound the native API's allocation.

Accepted observations require a valid self-relative revision-1 descriptor, bounded length and ACL pointer range, matching presence/defaulted control flags, valid ACL metadata and confirmed release. Only presence, NULL status, inheritance-protection/defaulted flags, count, allocated ACL bytes and revision enter the result. The application caps inspection at 4,096 entries and 65,535 ACL bytes, accepting revisions 2 or 4. These are application bounds, not claims about every Windows ACL. The production reader never enumerates ACE contents or copies/exports SIDs.

Absent DACL, NULL DACL and a present empty ACL remain distinct. No one of these states is a verdict about effective permissions, ownership or privacy. Sharing flags do not freeze `WRITE_DAC` changes; the query is a point-in-time source that can fail during concurrent security changes. Even a recorded nonempty/protected DACL grants no move or removal permission. `CanMove` remains get-only false.

The `NativeResult` field is the actual `GetSecurityInfo` DWORD result. It is not an HRESULT or the thread's last-error value. Successful query result zero does not establish validated facts. Later validation failures retain query zero but show Unknown; cleanup failures use their separate actual release error. No native zero is manufactured for uncalled APIs. The enclosing file preview and optional DACL status are independent, so an Available file observation never implies that its DACL or effective access was verified.

The normalizer binds DACL query times to the surrounding file-read interval and strips facts from invalid, failed, unsupported or otherwise unverified observations. It rejects contradictory absent/NULL/allocated shapes, invalid revisions/counts/bounds/times and success explanations on negative results. Missing optional observations stay Not checked. Actual unavailable/failure states and observed native/release codes remain separate.

Only the worker releases the descriptor. An unconfirmed `LocalFree` retains that one allocation and blocks all subsequent access-control queries for the app session; it never retries or grows a retained allocation list. A later blocked call reports that no new query/release occurred, without borrowing the previous file's status. Cancellation cannot close the caller's held file or free a descriptor still in use. Existing STA ownership and pending development-tree retention remain unchanged.

The owned Windows fixture compares real provider facts with independent native DACL queries on the same file identity. Its temporary in-memory audit copies only meaningful bounded ACL/control data, excluding allocator addresses and unused padding, then clears those copies. Nothing is persisted or exported except aggregate counts/flags and fixed validation results. It changes no ACL. Null/empty/denied/malformed/cleanup-failure native cases are not inferred from a normal inherited DACL fixture.
