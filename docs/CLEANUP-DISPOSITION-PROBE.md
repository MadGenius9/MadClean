# Owned classic file-disposition compatibility

This experiment exists only in the development harness. It accepts an exact marked artifact root and creates fixed inert files beneath it. It has no production scope, real-Temp/user-file API, configuration override or application executor. `ExecutionSupported` stays get-only false and client `CanDelete` remains false.

Fresh official [SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle), [FILE_DISPOSITION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info) and [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) documentation, plus official SDK headers, establish classic FileDispositionInfo class4, DELETE access and its one-byte BOOLEAN member. A successful mark is separate from handle closure and subsequent namespace observation. No EX/POSIX flags, readonly override, shell recycling, copy or path-deletion fallback is used.

The normal case holds the exact full-ID/stamp checked owned file with READ_ATTRIBUTES|DELETE and share0, under guarded ordinary ancestors. It sends byteTRUE with length1, separately records the actual call result/error, optional standard-information DeletePending flag, checked target close and actual GetFileAttributes error2 name absence after close. It claims no physical reclamation or general inactivity.

Six controls must invoke no disposition: readonly, recent, reparse parent, multiple links, changed file identity and a conflicting data writer. Writer-open32/33 belongs only to TargetOpenNativeError. An unobserved namespace result or unopened DELETE-target close stays null. Metadata-only handle cleanup is separate from actual target-close evidence. The changed-identity case opens and closes its mismatched target without mutation. If an owned link cannot be created, its coverage stays inconclusive.

Scope/marker/topology, full root identities, control bytes and checked handle releases gate cleanup confirmation. Refused files remain present at observation; later parent-owned fixture teardown is separate and can never make a failed primitive pass. Only the exact validated created directory link is removed nonrecursively to permit safe parent teardown. Readonly restoration is test teardown, never an eligibility bypass.

A sole worker owns native memory and handles. Pre-cancellation starts nothing; a45-second caller wait or later stop never force-closes native resources. Pending native work or an uncertain checked close retains ownership/tree and prevents later probes. A failed close is not retried against a possibly reused raw handle. Compact exported fields distinguish open, disposition and namespace errors; missing observations are explicit. Export overflow remains inconclusive and preserves known failures.

Independent review found no material blocker after correcting a writer-open error previously assigned to a namespace field and making target-close observations nullable.
