# Public Diagnostics repair review

The existing Windows integrity tools page now connects local effects review, four acknowledgments, existing-history recovery and request/result presentation through a portable controller and a guarded Windows facade. **Repair execution and history review remain unavailable in this build.** Local preparation starts no identity, history, servicing or repair query. Ordinary inspection and startup never invoke the flow.

## What the user can review

Selecting RestoreHealth or scannow and preparing a local draft shows the exact fixed command, effect, expiry, Windows log reference, source behavior and limits. DISM may use Windows Update/configured repair sources under Windows policy and includes /NoRestart. SFC scannow can repair protected files; no invented SFC restart switch is supplied. The candidate requires already-effective administrator rights and requests no UAC, credentials or relaunch. Restore points do not recover deleted files.

Operation/effects/permissions/observation acknowledgments are separate. They do not waive availability or security requirements. Confirmation remains disabled with closed flags, even when all four are checked. The initial controller permits one history review and at most one execution attempt per panel; no UI reset clears uncertainty or persistent history. This is an initial candidate limit, not a claim of a fully qualified repeat-repair workflow.

## Exact request and history admission

`SystemRepairReview` contains portable UI state, fixed selection/generation, exact request and immutable historical observations. Can* properties are cached and pure; they never consume confirmation or start I/O. Final confirmation rechecks current service flags/status, canonical qualified history, strict deadline, exact selection/generation and all acknowledgments before invoking the existing one-shot request confirmation. Selection/replacement/expiry invalidates draft acknowledgments. Busy state prevents reentrant command entry.

History must be the service's own completed, uncancelled, released, unblocked Reviewed result with nonempty identity and canonical complete empty/terminal records. Unknown, stopped, contradictory, partial or unreleased data cannot qualify. The facade independently applies the same prerequisites to its private actual memoized result, using the real shared servicing gate. Writer BeginIntent still rereads durable history; UI state is not dispatch authority.

`WindowsSystemRepairReviewService` has independent literal-false public execution/recovery guards before request/token/shared/native access. Its managed-only constructor composes the actual recovery reader/backend/workflow. Exact request reference plus generation binds its one cached execution attempt. Known preflight/capacity refusals perform no I/O; ambiguous task/ownership failures retain a bounded process-rooted service. No legacy executor or caller-supplied permission receipt is connected.

## Ownership, notifications and truthful results

The controller captures the caller's UI synchronization context for publications; cross-thread mutation is unsupported. The WPF adapter invokes it from the dispatcher, owns the actual task/stop source/global busy state and protects normal close until actual pending/retained resources settle. A stop request never kills Windows work or promises rollback; precommit cancellation follows the underlying protocol. Unexpected dispatcher shutdown and broader Windows behavior remain unqualified.

Notification failures cannot abandon an already-entered task. Individual subscribers are isolated, publication is reentrancy guarded, and presentation faults disable readiness. A failed service-ownership snapshot after an attempt latches uncertainty rather than publishing stale safe-to-close values. History-only blocks and presentation faults without actual unsettled ownership do not pretend a native process is running.

Request IDs, defined states, normalized client observations and exact bound direct contexts are checked before historical acceptance. Incomplete/inconsistent direct packets cannot claim resource release; bound uncertain raw facts remain explicitly unqualified. Recovery history, client exit/code, direct creation, reader EOF/worker release, cleanup and evidence consistency are shown separately. No raw output or Windows log contents are displayed. Exit0 and recorded terminal history never become repair success, healthy Windows or rollback; success and integrity remain Unknown.
