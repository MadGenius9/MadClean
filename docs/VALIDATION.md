# Validation and release gate

## Cloud capabilities

Linux can compile all projects using Windows reference packs and run portable core tests. It cannot run WPF, registry/Startup-folder inventory, Defender, WinGet's Windows execution alias or Windows Update Agent. Build success is not a rendered-UI or executable smoke test. See the current result record below for actual checks rather than assuming the CI workflow has run.

The test suite exercises old/recent/protected files, sharing violations, unreadable and missing paths, reparse loops and ancestors, overlapping scopes, inventory limits, cancellation before/during scanning, process cancellation/timeouts, malformed/localized/compact updater tables, unknown/truncated update status, strict Windows Update offer metadata and cancellation, unknown update types, fail-closed empty/relative scopes, dispatcher-independent process cancellation and bounded metadata-only log rotation. Ten filesystem-specific tests are explicitly skipped on Windows; junctions and ACLs still require Windows checks. New MadClean release tests use a fake HTTP handler to exercise missing configuration, pinned source/links, private/access/rate-limit responses, malformed metadata/tags, bounded notes/responses, network failures, cancellation and session reminder retention. New extension tests cover persistent exclusion round trips/boundary matching, invalid/concurrent/reparse settings protection, actual selected-folder metadata and bounds, logical-area conservation, local ARP path policy, removal restrictions, complete-registration comparisons and shared/user-path cautions. Firmware tests exercise source-specific CIM failures/ambiguity/placeholders, reported dates, generic OEM-guide identity/link boundaries, firmware-class versus title inference and non-Gregorian package-date formatting. No production provider is replaced or given placeholder success data.
