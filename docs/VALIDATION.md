# Validation and release gate

## Evidence and limits

The authoritative current ledger is [ROADMAP-STATUS.md](ROADMAP-STATUS.md). Linux uses SDK10.0.403/runtime10.0.14 to restore locked graphs, compile the full solution and run portable boundary tests. Linux cannot run WPF or Windows providers; cross-compilation is not runtime verification.

The portable suite covers filesystem permissions/reparse/locked/recent/overlap/cancellation/bounds; updater parsing and unknown states; Defender/WUA metadata contracts; persistent exclusions and disk-map conservation; registration/leftover restrictions; release-source/privacy/error behavior; firmware/hardware identity and uncertainty; full duplicate content and alias policy; shortcut ambiguity; minimized event/WER metadata and interrupted caller waiting; exact startup preview policy; and fixed system-tool descriptor/trust/consent gates. It never substitutes fake success into production providers. Counts, platform and current TRX location belong in the ledger rather than an assumed release claim.

The authorized Windows build job restores/builds/tests. Packaging an unsigned self-contained x64 executable is a separate manual option, disabled by default; ordinary pushes prepare no application ZIP. A separate disposable Windows harness loads the real App and renders its actual client content before populated UI metadata. Its later search check explicitly reads real CI-host registration metadata after every capture. Independently invoked native checks use owned duplicate/shortcut/registry fixtures, minimized Event Log/H1 hardware/application metadata queries and a disabled-system-tool boundary. Actual hardware/application values are never exported; the H1 check concerns only source/property/provenance schema, not device identity accuracy or compatibility. It does not delete user files, touch actual startup keys, launch servicing, scan with Defender, uninstall, install updates or reboot. The own-HWND sizing helper changes only the harness window's tracking bounds; no display setting or synthetic/reparented visual is used. Captured client content is not DWM/native-frame or physical-DPI proof.

No executable is called tested merely because compilation/package upload succeeded.

## Reproduce the cloud check

```text
dotnet restore MadClean.sln --locked-mode
dotnet build MadClean.sln -c Release --no-restore
dotnet test tests/MadClean.Tests -c Release --no-build --logger "trx;LogFileName=core-linux.trx" --results-directory artifacts/test-results
python -m unittest discover -s tools/tests -v
```

On the cloud host use /workspace/.dotnet/dotnet, DOTNET_CLI_HOME=/workspace/.dotnet-home and NUGET_PACKAGES=/workspace/.nuget/packages. The Windows harness targets WPF; Linux cannot normally resolve that shared framework to run Main. Its defensive platform guard is not a Linux smoke-test claim. Windows execution instructions and harness-only effects are in [tools/README-WINDOWS-VALIDATION.md](../tools/README-WINDOWS-VALIDATION.md).

## CI evidence integrity

Build/native jobs have read-only contents permission. Only the trusted source-bound publisher can write fixed bounded evidence to the existing private verification branch. Downloads must succeed with digest checking; rejected/missing downloads never admit leftover files. Every report/image is bound to the actual commit/run/attempt, PNG content is validated and hashed, and only fixed owned outputs are copied/pruned. Complete TRX result accounting, positive executed tests, successful jobs and a passing nonempty native report are all required for an overall scoped pass. Compiler/test text is retained only in bounded memory until comprehensive scrubbing, then scrubbed again before minimized excerpts. No production-provider logs, arbitrary files or force pushes are allowed. Raw counters, unknown stages and missing evidence stay visible.
