# Remember and recheck an MSI registration

Installed apps now has **Remember selected MSI product**, **Recheck remembered product** and **Clear remembered product**. This is useful before and after an external app change, but no uninstall is needed to use the recheck. MadClean never invokes an installer, uninstaller, repair, registry mutation or file action through this workflow. The public MSI dispatcher remains disabled.

Remembering requires the exact currently visible loaded registration and a fresh supported MSI metadata verification with one source-matching installed instance and matching name/version/publisher. Partial historical coverage and NoRemove restrictions remain visible; NoRemove does not forbid this metadata-only operation and is never overridden. The copied target contains a ProductCode, historical display/provenance/context and time, not an installation path, command or action token. It stays only in memory for at most 24 hours and deliberately survives later list selection/refresh. Clear or exit discards it. A capture in progress is invalidated by selection/source changes, including away-and-back changes.

Each explicit recheck creates a fresh two-minute read selector independent of the old action preparation/intent lifecycle. It reads only the exact ProductCode in HKCU shared, HKLM64 and HKLM32 ARP sources, then current-user managed/unmanaged plus machine MSI contexts. SID inputs/outputs stay null. Other profiles, every installed application and the filesystem are outside scope. Existing source-specific fresh action proofs are neither revived nor relaxed.

The source reader reuses the existing guarded root-to-leaf registry traversal, Query/Enumerate rights, REG_LINK refusal and bounded display/flag metadata. Uninstall names are probed with null data only; their contents are never read. The native MSI reader reuses exact-product `MsiEnumProductsExW` and whitelisted `MsiGetProductInfoExW`. These supported contracts and official references are in [selected MSI verification](MSI-REGISTRATION-VERIFICATION.md) and [selected-product preparation](MSI-SELECTED-PRODUCT-PREPARATION.md); no new action API or P/Invoke is introduced.

ARP Absent requires a genuine file/path-not-found code 2/3 from the exact supported traversal. Access errors, unsupported/link metadata and unknown reads do not imply absence. Missing native contexts become Absent only after complete exact-product mask-7 enumeration with zero issues. Actual Installed/Advertised observations remain separate; another context can still exist. Duplicates, malformed tuples/times and contradictory reports are rejected. Current reported name/version/publisher may differ from the historical target and never authenticate publisher or continuity.

All reads are sequential and non-atomic. **Available means observations were established, not that uninstall completed.** Registration disappearance cannot establish removed files, stopped processes, successful uninstallation or exclusive leftover ownership. Global inventory remains Not checked by this operation. Complete uninstall and leftover ownership remain Unknown; CanUninstall/CanDelete remain false. Existing baseline/leftover comparison is independent and is not silently refreshed or granted cleanup permission.

Preparation and watch share scheduled-before-start ownership plus the existing MSI-then-ARP admission order; resources/gates release only in actual worker cleanup. The worker has a 20-second cooperative budget and 45-second caller wait. Caller cancellation, timeout or Clear cannot close native handles or manufacture completion. UI Busy/normal-close protection drains the actual owner; late or invalidated results cannot repopulate the cleared/new view. Failure responses retain distinct Unsupported/Unavailable/Unknown/Failed states. No product fields enter the activity log.

Portable contracts cover capture/reference/mismatch/staleness, NoRemove read access, source/context absence versus unknown, changed metadata, incomplete enumeration, copied evidence, invalidation and cancellation. Native/WPF execution, context/permission variants and shared-reader refactor regressions still need Windows runtime validation. No personal product was uninstalled to test this feature.
