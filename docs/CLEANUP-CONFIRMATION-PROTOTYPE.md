# Owned confirmation protocol

This tool-only prototype exercises the action boundary using exactly marked developer files. It is not referenced by MadClean's production application, and ExecutionSupported remains false. A fixed developer branch is not real user consent or evidence that a client file is inactive, disposable or recoverable.

A private preview reference belongs to one session, exact held file identity/stamps and monotonic deadline. Root guards and the same READ_ATTRIBUTES|DELETE share-zero target handle remain held through the separate decision. The sole native request callsite uses classic one-byte FileDispositionInfo; there is no path-delete, recycle, EX/POSIX or readonly override fallback.

Independent owned cases cover decline, actual monotonic expiry, pre-cancelled decision, wrong session, affirmative confirmation and replay. Refusals issue zero disposition calls. Confirm and the first replay-case decision may each request disposition on separate files; a repeated decision must add zero calls. Request acceptance, native request error, optional delete-pending observation, checked target close and actual name absence are distinct facts. Refused source bytes/identities and independent controls are audited unchanged after handles close.

Caller waits are bounded; native work stays worker-owned. Pending work, uncertain native close or ownership/audit failure retains the worker and complete marked tree and stops later fixture mutation. No caller force-closes resources. One pre-cancelled protocol call verifies no startup. Root/file/metadata bookends are observations, not a universal namespace, inactivity or policy-freeze theorem.

The compact fixed case facts encode kind:decision plus c=calls, a=accepted, e=actual disposition error, p=delete pending, h=checked close, n=name absent, g=actual name-probe error, u=unchanged source and r=additional refusal/replay calls. Nullable unobserved facts remain separate from false or zero. No file IDs, paths, private preview references, bytes or dates are exported.

Independent static review found no material blocker. Local compilation is not execution proof; source-bound Windows results remain pending. Production cleanup, UI consent, protected-scope policy, active-use consistency and recovery remain separate unresolved gates.
