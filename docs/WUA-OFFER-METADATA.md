# Windows Update offer characteristics

Update Center now shows optional provider-reported manufacturer, provider and intended-device model names for driver/firmware offers, plus declared installation interaction, network, impact and reboot behavior. These are read-only properties from the existing configured-service search. No extra search, device identifiers, URL retrieval, asset download, installation, elevation or restart is added. The intended device model name is not an exact match to the user's attached hardware or motherboard revision.

Each field independently records Available, Unknown, Unsupported or Failed. Missing legacy metadata remains Unknown/not collected. A null InstallationBehavior remains Unknown even when the getter succeeded. A getter failure yields Failed without exporting its exception. False and enum value0 remain actual observed values; null or malformed values never become false/0. Software offers mark the three driver fields Unsupported, while their four installation fields retain their own coverage. A failed/malformed optional field preserves valid sibling fields and the actual base offer. Search success is separate from optional metadata coverage.

The supported enum values are installation impact0 Normal,1 Minor,2 RequiresExclusiveHandling and reboot behavior0 NeverReboots,1 AlwaysRequiresReboot,2 CanRequestReboot. These are provider declarations, not actual installation outcomes or a complete prerequisite assessment. They do not determine required elevation, exact OEM/device applicability, available BIOS/driver version, AC/battery precautions, recovery-key readiness or official manufacturer instructions. All those remain independently Unknown until verified. The existing RebootRequired property is separate from declared future installation behavior.

Driver strings are limited to512 UTF-16 characters and reject unsafe Unicode/control/format characters and unknown placeholders. Per-field JSON shapes, duplicates, types, enum ranges and version are validated. The producer projects at most256 offers and explicitly marks truncation; the parser rejects larger envelopes rather than silently accepting unchecked extra rows. A truncated search remains Partial, never Up to date. Required current reboot metadata must be an actual boolean; an unavailable value fails the base query rather than fabricating false.

- [InstallationImpact](https://learn.microsoft.com/windows/win32/api/wuapi/ne-wuapi-installationimpact) and [InstallationRebootBehavior](https://learn.microsoft.com/windows/win32/api/wuapi/ne-wuapi-installationrebootbehavior).

The separate disposable-CI update mode reports only counts of Available/Partial/Unknown optional-metadata rows in a strict source/run/attempt-bound version2 envelope. No field values, driver names, package identities or raw errors are uploaded. Its independent required check can pass only for genuine returned offers with at least one fully Available optional-metadata row. Software rows may qualify the shared four-field behavior projection; this does not validate driver-only getters or populated driver/firmware UI. Missing offers, source access failures and incomplete metadata remain inconclusive. No sample offers are injected into production.
