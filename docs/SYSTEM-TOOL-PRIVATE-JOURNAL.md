# Gated private operation-journal seam

The internal fixed-location facade and bounded reconciliation model support a future selected-action workflow. There are no App, startup, inventory or dispatch hooks. Production creation is immutably disabled before profile-path derivation, native opens or creation: ProductionCreationValidated is false and no runtime/configuration/UI switch bypasses it. This is not a production-ready writer.

The existing-only review factory derives the fixed current-user LocalAppData/MadClean/operation-journal-v1 location and opens existing objects read-only. It never creates the parent, directory or lease, repairs permissions, truncates files or fills in missing history. Missing source, failed access and malformed evidence remain unknown/unavailable; absence is not permission or proof no process is running. Fixed local-drive, ordinary ancestry, held identity, persistent-ACL and final-object owner/DACL checks are preserved. Reading must remain worker-owned when integrated; no UI integration is supplied here.

A separate internal factory uses only the exact marked developer GUID scope for validation. It holds an exclusive cooperating lease and validates protected current-user/SYSTEM security on held objects. Canonical GUID.jsonl records use CREATE_NEW, never overwrite, and append through the existing strict snapshot codec with flush and same-handle readback. At most128 journals,4096 bytes each and512KiB total are accepted. Unexpected names, mismatched file/record identities, unsafe objects, malformed tails, duplicate IDs, incomplete enumeration and uncertain I/O remain Unknown; no earlier healthy prefix is salvaged.

Unknown or unresolved evidence blocks another cooperating intent. Recorded terminal-only history and a complete empty source remove one historical block only. They establish neither authorship, machine-wide coordination, a running/stopped client, system health nor action permission. PIDs are never reopened or treated as identity proof. There is no automatic clearing, retention deletion, archival, reset or journal repair. Hitting the finite budget refuses new intents until a separately reviewed retention design exists.

Native security descriptor cleanup uncertainty is sticky. Checks immediately follow directory creation and precede another GetSecurityInfo allocation; failed cleanup cannot be followed by another security query. Source and descriptor ownership remain retained rather than retried or force-closed.
